# Робота з API(Application Progrmaing Interface)

## Освнови REST API
**REST API** - набір архітектурних правил для спілкування **клієнт-сервер**
Простіший за SOAP(Строгий XML формат + контроль безпеки) та використовує стандарти HTTP(HyperText Transfer Protocol).

**Ресурс** - логічна сутність(користувач/товар/стаття), сервер повертає не файли, а поточний стан ресурсу.

**URI(Uniform Resource Identifier)** - конкретний шлях до ресурсу. Формат: іменник(множ.) -> /users, /products/{id}.

**Безстановість(Stateless)** - Сервер ніколи не зберігає стан клієнта між запитами, кожен запит є незалежним і повинен містити потрібну інформацію, включно з токенами авторизації.

## HTTP-методи
Метод - конкретна властивість для взаємодії.
Ідемпотентність - властимість методу/ендпоінту, яка гарантує, що повторне виконання призведе до ідентичного результату, без додаткових змін сервера. 
- GET: Отримання даних(читання). І+ 
- POST: Створення нового ресурсу. І-
- PUT: Повна заміна ресурсу. І+
- PATCH: Часткове оновлення ресурсу. І+
- DELETE: Видалення ресурсу. І+

## Статус-коди
1. 2хх(Успіх) -> 200(Ok) | 201(Created) | 204(ok, without body).
2. 4xx(Помилка клієнта) -> 400(BadRequest) | 401(Unauthorized) | 403(Forbidden) | 404(Not Found) | 429(ToManyReuests)
3. 5xx(Помика сервера) -> 500(Internal Server Error) | 502 | 503 | 504.

## Формат даних та Серіалізація
**JSON** - баз. формат передачі(Словник).
**Де/Серіалізація** - перетворення об'єкта з МП в JSON-формат для передачі по мережі(де-зворотній процес).

## Безпека, Автентифікація та Авторизація
**Автентифікація** - перевірка особи(Хто я?).
**Авторизація** - перевірка прав доступу(Чи можу я?).

**Методи автентифікації:**
- Basic Auth(логін+пароль в заголовку).
- OAuth протокол який надає можливість авторизації без передачі пароля(Google/Telegram).
- API-Key(Авторизація через токен) -> Найпопулярніший - JWT(Json Web Token), принцип роботи ґрунтується на одноразовому надсиланні логін+пароль та повернення відповіді з токеном, який в майбутньому буде використовуватись для авторизації.

**SQL-ін'єкції** - рятує використання ORM(SQLAlchemy). А від DDoS - Rate Limiting. Усі дані мають передаватись через HTTPS.

## Вебхуки та підпис запитів
**Вебхук(WebHok)** - повідомлення зі сторони сервера про подію(Потрібен EndPoint)/Перевірка підпису/Швидка відповідь *200* і захист від повторної обробки події.

**Підпис запитів(HMAC)** - підписання запитів секретом, ідентичне потрібне для перевірки вхідних запитів. *Робота лише в .env*

### Стани операцій(1) та Pooling vs Webhook(2)
(1) *created -> paid -> delivered / failed.*
(2) Два різні способи отримання інформації про зміну статусу.

## Асинхронний HTTP-клієнт
*httpx.AsyncClient* or *aiohttp* -один спільний клієнт на весь проєкт, щоб не створювати новий для кожного запиту, **Requests** - синхронний клієнт.

## Додаткові інструменти
**Пагінація** - розбиття великих масивів даних на сторінки через параметри запиту(?page=2&limit50).
**Фільтрація** - пошук ресурсів за певними параметрами(?role=admin).
**Версіонування** - додавання версій в URL(https://.../v1/products) задля забезпечення сумісності при оновленні.
**Тестування** - Postman(app) | Curl(Terminal).

**Документація** - Swagger | OpenAPI автоматично згенерована документація з можлтивістю тестувати запити в браузері.
